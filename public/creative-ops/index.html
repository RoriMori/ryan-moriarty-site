AI + Automation

How AI and automation
live in the work

Three distinct tools with different costs, different requirements, and different returns. Knowing which to reach for, and when, is what makes the difference between a tech stack that scales and one that creates new problems.

AI is a tool I use to do better work, faster. The judgment, the relationships, the creative instincts stay human. The goal is always the same: work that connects with the right people and means something to the business.

Automation

Logic-based, no model. The cheapest and most reliable tool in the stack. Most teams underinvest here.

GenAI

Model-generated output. Copy, concepts, variations, summaries. Reach for it where judgment and creativity are actually needed.

Agentic AI

Multi-step, goal-directed. Highest value and highest cost. Requires a mature foundation before it delivers reliably.

Where automation runs

Logic-based, no model. Reliable, low-cost, and the right first move at almost every stage.

Beyond the workflow

Beyond producing work, AI can help teams build and run better systems. I use it to accelerate the audit phase: faster gap analysis and pattern spotting across inherited tools and workflows that would otherwise take weeks to map manually. I use it to read demand data at scale, surfacing volume and request patterns that inform how the ops system should be designed. And I use it to get documentation off the ground faster: SOPs, RACIs, and playbook drafts that give the team something real to react to rather than a blank page.

Once the system is running, AI becomes part of how it stays honest. Sense-checking processes as things change and flagging drift before it compounds into a bigger problem.

How I work with it

Not every problem needs the same model or approach. Part of working well with AI is knowing which tool fits the task and connecting it properly to the stack so it's actually talking to the tools already in use. How you structure the input matters as much as the tool itself: context architecture, clear instructions, and thinking about what the model actually needs to produce something useful rather than plausible-sounding noise.

I keep a human in the loop on anything that matters. Hallucination awareness and output validation aren't optional. And I manage context deliberately. Not burning tokens on noise keeps performance high and costs predictable. The prompts and system instructions I build are designed for consistency across the team, not one-off personal shortcuts.

Principles

How I think about
the work

A few operating principles that run underneath everything, the reasoning behind the methodology.

Connect early and often. Many things can be solved by opening a door and having a conversation. Relationships are the infrastructure everything else runs on.
Be programmatic in thinking, agile in doing. There are opportunities to carve out small wins and iterate often, while maintaining a clear path on the longer journey.
The tool is only as good as the process beneath it. The process is only as good as the methodology it's built on. And the methodology only works if you've earned the trust of your colleagues.
Enable functional clarity without sacrificing creative excellence. Operations exist to serve the work, not the other way around.
